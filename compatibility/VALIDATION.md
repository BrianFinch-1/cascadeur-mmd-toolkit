安装事务测试读取真实 Windows PE 文件和导出符号，在 Linux PowerShell 中仅
替换 Windows 路径解析和原生 VERSIONINFO 访问。没有执行原生 Windows
PowerShell 5.1 或 UAC 提权安装，不能将这些事务测试描述为 Windows 实机安装测试。

宿主窗口测试在 Cascadeur 的命令模式中创建独立 QML 菜单夹具；完整 GUI 在
当前 Wine 环境停留于启动阶段，未完成真实交互菜单和文件选择器的端到端验证。
最初 2026.2.3 烟测的原生崩溃已定位：PySide 的 `processEvents()` 释放 GIL，
宿主原生脚本定时器随后在没有 Python 线程状态时调用模块导入。移走全部插件
文件、确认未加载工具包模块后仍可复现；通过 `ctypes.PyDLL` 调用同一 Qt
接口并保留 GIL 的对照正常。烟测据此修正，产品流程没有加入事件循环，也没有
修改现代窗口实现。原生调用栈、反汇编与对照细节见 [INVESTIGATION.md](INVESTIGATION.md)。

另一个清理错误来自失效的 Python 主窗口包装器：原生窗口仍在原地址，增加
CppOwnership 本身不能阻止包装器失效。烟测重新枚举原地址的窗口，并检查
它的夹具属性和插件窗口是否全部释放，不再复用失效包装器。

现代模式的完整 ActionManager → D3D11 → 脚本服务器菜单点击仍需完整 GUI
验证；命令模式的独立窗口测试不覆盖这条原生菜单链。

没有用户具体 PMX/VMD 工程，未验证这些工程的整段动作导入、导出和 Scene Clean。
本次结论是安装兼容及上述旧版宿主能力测试通过，不是全部模型/动画结果的保证。
